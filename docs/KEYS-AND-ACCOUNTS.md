# Keys and accounts

Written 2026-10-15 and brought up to date on 2026-10-22 with the final code (all batches through R133). Every account, key and certificate the platform needs, in three groups: what you need today for local work (nothing), what is optional today (turns a mocked check into a real one), and what you need to go live. Names of secrets match `backend/src/types.ts` and `docs/INFRA.md` section 5; the order of steps is in [GO-LIVE.md](GO-LIVE.md).

Rules that apply to everything below:

* **Who holds an account matters.** Open every provider and payment account in the name of the legal entity that will invoice customers (owner question Q10 is still open: which entity). Use a shared company mailbox such as `ops@<your domain>` as the login email, not a personal one, and turn on two-step sign-in everywhere.
* **Keep one password manager vault** for the company with these items: every key below, the Android keystore and its passwords, the Windows certificate, the `CREDENTIALS_KEYS` value, and recovery codes. Losing `CREDENTIALS_KEYS` makes stored agency provider keys unrecoverable.
* **Never** put a real key in the repository, in `landing/config.js`, or in a `NEXT_PUBLIC_*` variable (those are public). Local files `backend/.dev.vars`, `desktop/.env.local`, `terraform/terraform.tfvars` and `packages/driver_app/android/key.properties` are git-ignored; keep them that way.
* **Everything that was ever in the public repository is compromised.** Production must use brand-new values for every secret (GO-LIVE phase 0). Owner decision 2026-10-21 (R100 deferred): the repository stays public for now, you say the exposed keys are invalid and every secret in it is a dummy; making it private and rotating is postponed, but must be done before the first real key is created.
* **Never set `TEST_MODE` or `BILLING_GATEWAY=mock` on staging or production** (the mock payment secret has a public default).
* Prices below are list prices from `docs/COST-MODEL.md` (retrieved October 2026, some from third-party trackers); get a current quote before paying.

One owner action, not a key: make the GitHub repository `sn-arjun/travel-crm` private and revoke the old token (GO-LIVE phase 0; postponed by the owner on 2026-10-21, due before any real key exists).

### 3.2 Generated secrets (you make these; no account)

Run each command in a terminal at the repository root (Node 22 is installed). Each prints one value; copy it to the password manager first, then set it where the table says. Use a **different** value for every row, and different values for staging and production.

| Secret | Used by | Generation command | Where it goes |
|---|---|---|---|
| `JWT_SECRET` | API | `node -e "console.log(require('crypto').randomBytes(48).toString('base64url'))"` | Worker secret (backend) |
| `JWT_REFRESH_SECRET` | API | same command, run again | Worker secret (backend) |
| `SUPER_ADMIN_JWT_SECRET` | API and console (same value in both) | same command, run again | Worker secret on both `travelcrm-api` and `travelcrm-super-admin` |
| `CREDENTIALS_KEYS` | API: seals agency provider keys (Meta, payment gateways), voice sub-account tokens and two-factor secrets | `node -e "console.log(JSON.stringify({k1: require('crypto').randomBytes(32).toString('base64')}))"` | Worker secret (backend). `CREDENTIALS_ACTIVE_KEY_ID` is generated as `k1`. Keep a copy forever; losing it makes all of those unrecoverable |
| `HEALTH_TOKEN` | API; uptime monitor header `X-Health-Token` | `node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"` | Worker secret (backend) and the monitor |
| `INBOUND_EMAIL_SECRET` | SendGrid Inbound Parse URL path | same as `HEALTH_TOKEN` | Worker secret (backend), and in the SendGrid Inbound Parse URL |
| First operator password | Console sign-in (the console has no two-factor yet) | A long passphrase of 12 or more characters you make up | Typed once into `create-super-admin.mjs`; stored only as a hash. Keep in the password manager |
| Agency user passwords | Seeded demo passwords such as `Admin@123` | Change them before go-live. New and changed passwords need 12 or more characters (R209); older short ones still sign in | Never reuse; never record |
| `UNSUB_SECRET` | API: signs the unsubscribe links in marketing messages (R208). If unset it is derived from `JWT_SECRET`, and rotating `JWT_SECRET` would break every link already sent | same command as `HEALTH_TOKEN` | Worker secret (in `push-secrets.sh`) |
