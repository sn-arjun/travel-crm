# B28 requests for shared changes

1. `src/hooks/use-feature-gate.ts`: `UPGRADE_HREF = '/settings/billing'` points at a route that does not exist (404 on every gated page). Either add a billing page or point it at `/settings/ai`. B28 components use `/settings/ai` locally.
2. Backend (B30/backend owner): when the Workers AI binding is missing, `/ai/extract-lead`, `/ai/generate-itinerary`, `/ai/compose-message` return HTTP 200 with a stub `{ note: "Cloudflare AI not available..." }` payload. B28 detects this client-side (`AiUnavailableError` in `lib/api/ai.ts`); a proper 503 `AI_UNAVAILABLE` would be cleaner. `/ai/intelligence/nl-query` in the same situation returns a misleading "I couldn't generate a query" narrative with no stub marker.
3. `GET /ai/settings` `provider.cloudflare` is always `true`, so the UI cannot tell whether the AI binding exists.
