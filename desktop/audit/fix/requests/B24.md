# B24 shared-file requests

1. `src/app/(app)/dashboard/dashboard-data.ts` (B18-owned): `reportsApi.execute<T>()` and a typed `getDashboard()` (`DashboardResponse`) now exist in `src/lib/api/reports.ts`. The casts in `dashboard-data.ts` (`unwrapEntity<Partial<DashboardSummary>>`, `reportRows<T>`) can be replaced with `reportsApi.execute<T>(...)` and `unwrapEntity<DashboardResponse>`. Not touched here because the file is outside the B24 allowlist.
2. Backend (B12 follow-up): `previous_period` for ungrouped multi-row reports returns only the first row, so the report pages do not use it. Compare mode instead runs each report a second time for the equal-length window just before the selected one (`previousRangeParams` in `report-page-template.tsx`). A real `previous_period` for multi-row reports would let this drop the second request.
3. Backend: `fleet_availability` applies the date range to `vehicles.created_at`, which is meaningless for a current-status snapshot. The Fleet page hides the range control on the Availability tab; the report should ignore the range the way `birthday_upcoming` and `dormant_customers` do.
4. Backend: report engine caps rows at `per_page` (default 25, max 500); pages request 100. Lists longer than that are truncated without a "more" indicator because `meta.total` is `-1` when a page is full.
