# B29 requests for shared / other-batch files

1. `desktop/src/lib/api/visa.ts` (owner: B30 / B11) - `CreateTravellerRequest` and `UpdateTravellerRequest`
   do not list the traveller columns the backend already stores: `frequentFlyerNumbers`, `mealPreference`,
   `seatPreference`, `emergencyContactName`, `emergencyContactPhone`, `medicalNotes` (the `Traveller`
   read type has them). B29's traveller forms send them through `travellerExtraPayload()` in
   `travellers/_lib/form-shared.tsx`, which compiles only because the payload is built as a variable.
   Please add them as optional fields to both request types, then the helper can be typed directly.

2. `desktop/src/app/(app)/settings/import/page.tsx` (owner: B27) - B29 made two small edits here because the
   batch hand-off required them (`import-export.spec.ts:508`):
   - the import-history `ListPage` now receives `filters={activeFilters}` (+ `onRemoveFilter` / `onClearFilters`),
     so the type/status selects refetch the list;
   - the contacts mapping no longer offers a `Type` target (the import backend ignores it and always creates
     `type: 'customer'`).
   Four `no-explicit-any` lint errors remain in that file (lines ~95, 151, 168, 213) - B27 owns them.

3. Contacts import mapping: contacts have a single `name` column, but the backend import validator
   (`backend/src/services/imports/import-validator.ts`, contacts schema) requires `firstName` and joins
   `firstName + lastName` into `name`. The mapping targets therefore stay First Name / Last Name (the specs
   assert them); a backend change to accept a single `name` column would let the UI offer "Name" instead.

4. `desktop/src/components/domain/list-page.tsx` (B30) - no controlled/initial search prop. After a rename in
   documents the search box keeps the old name, so the renamed row is filtered out (spec updated to re-search).
   A `searchValue`/`onSearchChange` pass-through would let the page clear the box after a successful edit.
